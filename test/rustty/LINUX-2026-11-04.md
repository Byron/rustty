Starting revision: `a90e26835`. Production changes target Rustty only.
References are the local Ghostty sources and `../kitty` sources/specifications.
The available Linux machine is ARM64 (Neoverse-N2), not x86; x86 performance
claims require a separate machine. These headless checks do not measure visible
or rendered latency.

## Pointer shape stacks and queries

Rustty now follows Kitty's `docs/pointer-shapes.rst`, `window.py` dispatcher,
and `screen.c` stack lifecycle: each screen owns 16 entries, overflow evicts
the oldest, setting replaces the top, pushing appends, and popping ignores its
name list. Unknown names are ignored; an empty set requests the default while
preserving earlier entries. RIS and DECSTR clear both stacks.

OSC 22 queries report supported canonical shapes, the current application
shape (or `0`), and the actual default/grabbed fallback (`text` for both in
Rustty). Responses preserve BEL/ST termination. Pointer changes leave text,
selection, history, cursor position, and content generations unchanged.

Optional snapshot records retain both stacks and parser continuation without
changing the snapshot or tmuxx protocol version. Older readers retain the active
resolved shape through the existing header; older snapshots seed both screens
from their terminal-wide shape. Both native snapshot encodings, detached
viewport snapshots, and attached views preserve the new state.

Validation:

```sh
cargo test --locked --offline -p rustty-vt \
  --test pointer_shapes --test osc_strings --test snapshot
cargo test --locked --offline -p tmuxx-terminal --test pointer_shapes
cargo test --locked --offline -p rustty --features sessions --lib \
  native_views_preserve_pointer_stacks_across_output_and_reconnect
```

The checks cover every query byte split, both terminators, overflow/default
entries, both screens and reset paths, malformed snapshot records, legacy
snapshots, two independently attached views, live output, and reconnects.
Native pointer rendering was not exercised on Linux.

## Working scrollback compression

The accepted `scrollback-compression` setting had no runtime consumer. It now
controls lossless LZ4 storage for cold historical packed-cell buffers. Row IDs,
headers, styles, graphemes, hyperlinks, selection, and logical history limits
remain intact. Active and viewport pages are excluded. Shared reads lazily
restore an immutable cache; exclusive recompression can release that cache
without running the codec again. Incompressible buffers and buffers larger than
1 MiB stay resident. Existing snapshot formats and protocol versions are unchanged.

Each idle step scans page metadata, inspects at most eight candidate pages, and
attempts at most one bounded cell-buffer compression. Partial page trims reset
the traversal. Local Session uses its existing writer with a coalesced request,
an idle delay, and no maintenance wakeups after the pass completes. Native and
embedded tmuxx connections reuse their existing idle turns, visiting independent
attached views fairly. The remote tmuxx owner has no corresponding config
setting and its policy is unchanged.

Output, config changes, resizes, and full visual captures re-arm local work.
Viewport snapshots restore detached copies without re-arming the source.
Arbitrary shared VT reads may keep restored buffers resident until later host
activity; compression is opportunistic. Disabling prevents further compression
while existing encoded buffers remain readable on demand.

Validation:

```sh
cargo test --locked --offline -p rustty-vt --lib
cargo test --locked --offline -p rustty-vt \
  --test snapshot --test unscroll --test selection_format
cargo test --locked --offline -p rustty --features sessions --lib compress
```

All 226 tests passed, including exact cell and snapshot identity, resource-rich
history, selection and tracked row IDs, mixed screen lifecycles, partial trims,
reflow/unscroll, memory limits, PTY config reload, full-capture recompression,
idle disarming, and independent native-view policy across reconnects.

On 20,000-record corpora, owned history fell 83–93%; first cold-page access
took 153–190 µs. Paired resident controls retain a 2.4–2.9% feed cost,
up to 1.3% stream cost, and 4.1–10.8% read cost (up to 0.32 µs).
Both variants used Rust 1.99.0. Measurements, limitations, and reproduction
are recorded in [BENCHMARKS.md](BENCHMARKS.md#linux-scrollback-compression-2026-11-04).
Kitty's checked-out `history.c` retains older evicted text in a separate ANSI/
UTF-8 pager ring. That ring cannot serve interactive scrolling. A second pager
tier is deferred: the implemented compression already provides substantial
interactive-history savings, and no additional benefit has been demonstrated.

## Save and restore side-effect-free modes

Kitty's parameterless `CSI ? s` / `CSI ? r` now saves/restores supported ANSI
and DEC modes, including input encoding, cursor appearance, and host reporting.
It excludes modes 3, 6, 40, 47, 69, 1047, 1048, 1049, and 2026 so restoring a
TUI's modes cannot resize/clear the grid, move the cursor, alter margins, switch
screens, or release/restart a synchronized-output hold. Explicit lists retain
their existing semantics; an explicit zero is not a parameterless request.

Mouse tracking and coordinate encoding retain both the saved bits and the actual
encoder selection. An optional snapshot record preserves that selection without
changing the wire version. Linefeed and focus updates use the existing ordered
host callbacks. RIS resets the additional saved state.

```sh
cargo test --locked --offline -p rustty-vt \
  --test save_all_modes --test modes --test snapshot
cargo test --locked --offline -p tmuxx-terminal --test save_all_modes
```

## Unscroll

Kitty's `CSI Ps+T` restores primary interactive history into the current SD
region without moving the cursor. Explicit zero is inert, each request is
bounded to one screen, and exhausted history or an alternate screen uses
ordinary SD blank rows in the current background. Full-width restoration moves
retained rows and their identities rather than cloning them; partial-width
restoration uses existing resource-safe cell copies and repairs clipped wide
characters. Selection and image anchors survive only where their source
content is restored. Newly active narrow history rows extend safely beneath
an existing cursor after snapshot restoration.

This follows `../kitty/docs/unscroll.rst` and
`screen_reverse_scroll_and_fill_from_scrollback`. One deliberate difference is
nonzero margins: Kitty currently copies restored history to physical row zero
after scrolling its region; Rustty restores at the configured top margin and
preserves SD geometry outside all margins. With horizontal margins, the consumed
history row's cells and anchors outside the restored columns are discarded.
This consumes interactive scrollback, not text retained separately for a pager.

```sh
cargo test --locked --offline -p rustty-vt --test unscroll
cargo test --locked --offline -p rustty-vt --lib \
  unscroll_across_pages_preserves_resource_ownership
cargo test --locked --offline -p rustty-vt --test snapshot \
  unscroll_widens_restored_history_beneath_an_existing_cursor
cargo test --locked --offline -p rustty-vt \
  --test reverse_index --test stream_controls
```

Nine unscroll regressions, the cross-page resource test, the mixed-width snapshot
test, two reverse-index tests, and eleven stream-control tests passed. Coverage
includes every input split, both terminal profiles, margins, row IDs, pending
wrap, rich cells, selected/image anchors, clipped wide cells, empty history,
alternate screens, large/invalid counts, and snapshots. These are Kitty
specification/reference regressions, not Ghostty unscroll differential results.

## Program-status records

OSC 7501 reports now retain kind, progress, app, title, and message. The reusable
VT record store validates at most 256 records, replaces complete records, clears
ID subtrees, inherits app names from the nearest ancestor, and ranks urgency by
last change while evicting by last report. Serialization preserves both orders.
The existing 128-byte ID limit and strict base64 validation remain unchanged;
Kitty expands its ID limit to 263 bytes. Kitty's private `process-exited` body
remains unsupported; hosts use real process/prompt lifecycle hooks.

```sh
cargo test --locked --offline -p rustty-vt \
  --test program_status --test program_status_records
python3 test/rustty/kitty-program-status-reference.py ../kitty \
  > /tmp/kitty-program-status.json
cmp test/rustty/fixtures/kitty-program-status.json /tmp/kitty-program-status.json
```

Eight tests pass. The checked-in fixture runs 20 lifecycle scenarios and a
256-record eviction scenario directly against Kitty `8f6dceb61836e014d831ba941166ae7a5822855b`.
The harness substitutes only `fast_data_types.base64_decode` with Python's
strict standard-library decoder; parsing, record ownership, urgency, inheritance,
and lifecycle code are Kitty's unmodified implementation.

Program status is enabled for local PTY sessions and native tmuxx pane owners.
`Session::program_status()` queries the same records restored into attached
views. tmuxx exposes the most urgent state/progress/app/title/message and a full
resolved JSON query via `pane_program_*` formats. Direct and tmux-wrapped support
queries receive exactly one owner reply. Optional checkpoint record `0x8004`
preserves both record orderings without changing protocol versions or copying
process status into display-only new-shell handovers.

```sh
cargo test --locked --offline -p rustty-vt \
  --test program_status --test program_status_records
cargo test --locked --offline -p tmuxx-terminal --lib program_status
cargo test --locked --offline -p tmuxx-core --lib program_status
cargo test --locked --offline -p tmuxx-runtime --lib program_status
cargo test --locked --offline -p rustty --features sessions --lib program_status
```

The 19 focused tests cover real local PTY discovery and final output/exit,
primary versus continuation prompts, hard/soft reset, focus/input acknowledgment,
two-view focus, synchronized input budget rejection, query enumeration,
full/compact fragmented snapshots, bounded malformed/maximal metadata, and
attached-view resynchronization without duplicate replies/actions. The runtime
PTY admission test requires permission to spawn PTYs on Linux (the restricted

No renderer or native desktop status UI was added. Paste, mouse, replies,
composition, key release, and rejected input do not acknowledge unseen results.
Transient cleanup waits for drained PTY output, avoiding the child-waiter race.

## PTY and parser results

The [PTY benchmark report](PTY_BENCHMARKS.md) records the Ghostty/Kitty source
inspection, corrected real-PTY harness, raw samples, executable/source hashes,
commands, and baseline/candidate/candidate/baseline comparisons. Rust 1.95.0
release builds were complete before timing; other builds and benchmarks were
stopped. Ordinary sessions, embedded tmuxx, and native sockets were measured
separately because their parsing and delivery paths differ.

| Measured boundary | Before | Retained implementation |
| --- | ---: | ---: |
| Ordinary ASCII throughput | 158.58 MiB/s | 235.18 MiB/s (+48%) |
| Ordinary styled/mixed throughput | 49.95 MiB/s | 52.88 MiB/s (+6%) |
| Ordinary sparse parsed-echo median | 51.44 µs | 59.41 µs |
| Ordinary 64 KiB burst plus DSR median | 511.05 µs | 404.01 µs |
| Embedded parsed-echo median | 3067.04 µs | 98.82 µs |
| Embedded paced ASCII throughput | 34.70 MiB/s | 70.70 MiB/s (+104%) |
| Embedded paced styled/mixed throughput | 9.70 MiB/s | 10.97 MiB/s (+13%) |

Ordinary gathering costs one additional worker and a fixed 128 KiB buffer pool
instead of 32 KiB. Small requests add about 8–10 µs, and the 64 KiB post-write
tail grows from 151 to 196 µs while total burst completion improves. Embedded
workers remove the fixed polling delay; owner-side DSR timings remain largely
unchanged. A native-socket control completed normally, without a claimed speedup.
Paced throughput includes view acknowledgments at complete-record boundaries.
These results measure PTY/parser/view delivery, excluding rendering and display.

Compression is measured independently with Rust 1.99.0 in
[BENCHMARKS.md](BENCHMARKS.md). The 20,000-line corpora reduce owned history by
83–93%; first cold-page reads take 153–190 µs. Resident controls show 2.4–2.9%
more feed time, up to 1.3% more stream time, and up to 0.32 µs more time to read
4096 resident cells. These costs remain explicit rather than being combined
with the independent PTY speedups.

All 33 ordinary session tests, four new runtime admission/accounting tests, and
71 Linux tmuxx tests passed; one existing SSH fixture is ignored. Tests cover
final-output ordering, cancellation, input backpressure, snapshot acknowledgments,
idle/busy worker release, borrowed views, compression, status, and reconnects.
The selected Ghostty comparisons elsewhere in this report total 1,161 cases;
Kitty-only additions have their own focused reference/specification regressions.

## Concrete deferred work

- Native desktop/renderer validation: keyboard-hint UI, drag-and-drop,
  actionable notifications, scaled text, indexed-image rendering,
  multiple-cursor rendering, program-status presentation, and native pointer
  appearance. This work does not port the desktop or font backends to Linux.
- x86 SIMD changes require measurements on x86 hardware. The available ARM64
  host cannot establish their benefit. Existing scalar-equivalence tests and
  the recorded parser baselines provide starting points.
- Unpaced embedded 16 MiB output still disconnects the bounded subscriber.
  The harness retains this failed stress case explicitly. Per-client backlog
  handling needs a separate design that preserves owner responsiveness and
  replay order; removing polling does not fix that overload.
- A second compact pager-history tier has no demonstrated additional benefit
  after the interactive-history compression savings. The tmuxx owner has no
  matching compression config; the current policy applies to local sessions
  and attached views.
- Existing saved-cursor resize and cursor blink-default reset differences
  reproduce at the starting revision, as detailed above. Full Ghostty parity
  remains unestablished.

The output-coalescing experiment was rejected: fewer callbacks did not improve
throughput, and styled/mixed throughput regressed. Its source patch and results
are preserved with the benchmark artifacts, outside production implementation.

## 2026-11-05 continuation: cold-history navigation

Rows now skip with page metadata, anchor validation avoids cell reads, and short
selection formatting opens only selected pages. Search setup reads frontier IDs
and wrap flags without decoding older pages. tmuxx restores selected views with
the same metadata-only endpoint validation. Row identities, physical widths,
snapshots, native formatting maps and selection behavior remain unchanged.

The [navigation report](HISTORY_NAVIGATION.md) contains focused regressions and
three adjacent benchmark pairs per size/corpus, with Rust 1.95.0 on Linux ARM64.
At 250k ASCII rows, viewport reads fall from 21.97 ms to 3.8 µs, short selections from
24.54 ms to 0.36 ms, and first-search feed from 33.87 ms to 3.80 ms while avoiding 239.6 MB
of decoded cells. First-search setup retains linear metadata/formatting work.
These are core access timings; owner compression and full-history search remain
separate steps, and no rendered or visible latency is claimed.

## 2026-11-05 continuation: detached and remote owner compression

The tmuxx owner now runs finite, fair idle compression passes using the existing
VT codec, checking events and scheduled work before each page. Creation,
respawn, real resize, reset, capture and native snapshot lifecycles request
maintenance, including failed captures and rejected snapshots. Metadata polling
stays inert, and attached views retain their independently configured policy.
This completes the owner-policy item deferred in the original report above.

The [owner report](OWNER_COMPRESSION.md) records 36 paired real-PTY runs on Linux
ARM64 with Rust 1.95.0, plus lifecycle and error-path tests. At 100k rows, owned
primary-page storage falls 95–96%; single-pane process RSS remains similar.
Feed-time medians change by at most +2.3%. Cold full captures cost 33–37% more
and fresh native attach 5–9% more, with their synchronous latency and the remote
DSR outlier retained explicitly. These savings exclude screen-level metadata,
graphics and other views, and are separate from visible or rendered latency.
All 194 targeted VT, wrapper, core, runtime and Connection tests passed.

Three additional pairs with four sequential 100k Unicode panes demonstrate
reusable storage: summed primary pages 421.35 → 16.93 MB, process RSS
744.7 → 209.0 MB before any capture/snapshot. All 24 later old/final-text
checks pass. The owner report retains creation time, CPU and cold-access costs.

## 2026-11-05 continuation: full-history search

History windows now use their known page directly, and synchronous search
refreshes active contents once per call. Incremental feed semantics remain
unchanged. The separate [search report](HISTORY_SEARCH.md) records 36 paired
runs after the shared navigation prerequisite: cold search improves 44–67%,
with 250k ASCII 1576.12 → 548.47 ms and Unicode 1117.76 → 365.37 ms. It still
reads all historical cells and remains a synchronous core cost. All 94 focused
search, selection, formatting and snapshot tests pass.
