# Linux continuation: delivery, compatibility, and retained history

Starting revision: `247ad8119`. This continues the historical
[November 4 report](LINUX-2026-11-04.md). Rustty is the implementation target;
Kitty at `../kitty` and Ghostty production sources remain read-only references.
The machine is Linux ARM64 Neoverse-N2 with 16 logical CPUs. Rustty has no Linux
desktop application; these checks exercise terminal libraries, PTYs, sessions,
and tmuxx, without claiming rendered/visible latency or power savings.

## Results and reproduction

Comparisons use Rust 1.95.0, generic ARM64 release builds, thin LTO and one codegen
unit with matching workloads/profiles. Reports retain frozen baselines, exact
source patches/hashes, harnesses, lockfiles, run order and raw results. Most
focused checks use Rust 1.95.0; saved-cursor/default-cursor focused suites and
the two content-format tests used the documented default Rust 1.99.0 toolchain.
The compatibility differential adapters used Rust 1.95.0. No x86 performance
experiment was possible.

- [Delivery recovery](DELIVERY_RECOVERY.md) fixes the original unpaced 16 MiB
  subscriber failure. Paced native throughput is 2.5–2.8% lower in the recorded
  pairs; the retained benefit is recovery correctness, not a throughput claim.
- [Native restore limits](NATIVE_SNAPSHOT_LIMITS.md) permit retained large-history
  views without weakening header, active-page, continuation or graphics checks.
  The independent ceiling counts up to 8 GiB of packed cells across the graph;
  it is not a total RSS bound. Wire/snapshot versions remain unchanged.
- [Cold navigation](HISTORY_NAVIGATION.md): at 250k ASCII rows, viewport access
  falls from 21.97 ms to 3.8 microseconds and short selection from 24.54 to
  0.36 ms, avoiding 239.6 MB of restored cells.
- [Content formats](CONTENT_FORMAT.md): at 100k rows, lookup falls from 66.5 ms
  to 11.7 microseconds; matching semantics are unchanged.
- [Receiver restoration](SNAPSHOT_RESTORE_PERFORMANCE.md): a 250k styled native
  restore falls from 1.11 s to 522 ms; plain controls and owner checkpoint
  construction remain essentially unchanged.
- [Owner compression](OWNER_COMPRESSION.md): four sequential 100k-line panes
  reduce primary-page storage from 421.35 to 16.93 MB and same-process RSS from
  744.7 to 209.0 MB. Later window creation falls from 46.6–94.5 ms to 7.7–20.1 ms.
  Single-pane RSS barely changes; cold capture costs 33–37% more and native
  attach 5–9% more. Whole-job CPU, RSS and individual latency samples are recorded.
- [Shared-owner pressure](OWNER_PRESSURE.md): native two-burst and embedded
  three-burst runs recover every retained row ID/text. Native three-burst readers
  held for about 11.95 s still hit the existing 10 s write timeout; reconnect
  recovers all 95,277 retained rows. Synchronous snapshot stalls remain.
- [Full search](HISTORY_SEARCH.md): cold search improves 44–67%; 250k ASCII and
  Unicode cases still take 548 and 365 ms. These are fresh-query core timings,
  not displayed search latency. Reflow/recompression diagnostics are retained
  in the owner report; no new reflow optimization is claimed.
- [Bounded capture](CAPTURE_RANGES.md): at 100k rows, cold visible capture falls
  from 6.961 ms to 4.58 microseconds and restores zero unrelated cold cells.
  Four historical rows fall from 6.941 ms to 16.54 microseconds and restore only
  their selected page. Full cold controls change by +0.51% at 100k and +1.25% at
  20k; a prior trial with a 7–10% full-capture regression was rejected.

Owned-page measurements count cell buffers and page-local row/style/link/grapheme
allocations, including active primary pages. They exclude screen-level metadata
maps, graphics and other process state. RSS includes allocator retention and,
where documented, in-process models/views and verification. PTY throughput,
owner-command latency, child DSR replies, parsed-view delivery, receiver restore,
CPU and RSS remain separate measurements.

## Concrete limits

- Recovery queues have finite byte/record limits. Critical floods, oversized
  barriers and the existing socket timeout can still disconnect a client.
- Full capture, snapshot creation/restoration, search and reflow remain
  synchronous large-history operations. The 100k pressure runs retain owner
  command maxima up to 1.20 s and parsed-view echo maxima up to 2.73 s;
  bounded compression work is not a general latency guarantee.
- Compression is opportunistic and preserves interactive history limits. Idle
  pages stay encoded; active/viewport pages and resources stay native. Arbitrary
  library reads still require their host to rearm maintenance as documented.
- The installed tmux 3.6 reference lacks newer capture flags. The capture report
  distinguishes 38 filtered C comparisons from 317 unchanged Rust fixture
  results and documents two pre-existing older-C tab differences; no full
  modern C-reference pass is claimed.
- A separate pager-history tier has no demonstrated additional workload benefit.
- Native status presentation, keyboard hints, pager UI, drag-and-drop, desktop
  notifications, renderer row caching, indexed images, text sizing and multiple
  cursors remain desktop-capable work. No Linux GUI/font port was attempted.
- x86 SIMD remains deferred until actual x86 hardware is available. No tuning
  options or architecture-specific implementation was added.
