## Rust surfaces and behavioral guarantees

- **Actual boundary:** `crates/rustty-vt/Cargo.toml` defines a Rust library with public Rust modules in `src/lib.rs`; it has no C ABI or GhosttyAllocator/ghostty_type_json consumer. Its only Cargo feature switches are allocation instrumentation and scalar kernels, not optional terminal API modules. Desktop and tmuxx code call Rust Terminal, Screen, input, search, renderer and snapshot types directly. The native comparison tool uses Zig `vt.Terminal` plus `vt.TerminalStream` directly, not `src/terminal/c/terminal.zig`'s wrapper. Root confirmed the refreshed native build and comparisons use that path.
- **Empty continuation:** `rustty-parser/src/lib.rs:393`, `Parser::continuation`, returns `Ok(result)` where an empty retained tail creates an empty Vec. `tests/continuation.rs` already covers successful empty tails after final input, validates an empty canonical continuation, and recovers to empty after overflow reaches ground. `6dc6cd927` fixes only the C null-buffer size-query return code; Rust already expresses the result correctly.
- **Search navigation:** `rustty-vt/src/search/terminal.rs:206` exposes `TerminalSearch::select(Direction, SelectScroll)`. `choose` handles first/last selection and wrapping next/previous indices; desktop `rustty-app/src/search.rs:54` calls both directions. Existing search tests assert wrapping, independent terminal selections, missing needles and per-surface state. New C functions merely replace action keys that already called the same core routine.
- **Combined Kitty layer filters:** `rustty-render/src/graphics.rs:prepare_graphics` builds `[Vec<Quad>; 3]`, sorting `(z,order,placement)` and classifying below-background, below-text and above-text at the same z thresholds. Rust callers also have direct placement iteration/filtering. The C enum-to-bitmask change adds combination convenience to its restricted iterator, without a new renderer capability or wire behavior to port. Explicit placeholder-kind and transmission-age bugs are separately tracked in behavior audit.
- **Current image pixels and absence:** Rust `Image::display_pixels`, `displayed_pixels`, `has_pending_pixels` expose length-bearing pixels and distinguish pending snapshot sources; renderer `display_source(...).is_empty()` skips absent image data. Width and height are explicit fields. Combining C data_ptr/data_len into one String and adding expected_len does not reveal new data unavailable in Rust.
- **Initialized callbacks:** `Terminal::EffectHandler` returns fully initialized `Option<query::ColorScheme>`, `Option<DeviceAttributes>`, `Option<Size>`, Vec replies and typed clipboard results. Default query callbacks return None or empty Vec, and clipboard callbacks return Denied. Host code cannot partially write an uninitialized Rust response as C can. `query.rs` uses typed exhaustive enums. Existing `host_queries.rs`, `host_effects.rs`, `host_shell_events.rs`, clipboard and program-status tests exercise synchronous host paths. Frozen C callback layouts and zero-init therefore have equivalent guarantees without reproducing foreign ABI structs.
- **Bounds and missing values:** Rust input encoders and query reply helpers return Vec, formatters write owned String, cells expose typed RowView text/style and optional hyperlink data, and `RenderView::cursor` returns Option. C CodepointBuffer capacity/required-size and no_value consistency changes make these guarantees explicit for raw pointers; Rust APIs already carry lengths and absence in types.
- **Input settings and example correction:** Rust KeyEvent/MouseEvent contain typed enums, `Option<MouseButton>` and text. `KeyEvent::plain` initializes the unshifted character for ASCII keys; desktop `input.rs:542` gets it from the unmodified key. Thus `ad89e75cc`'s Ctrl-C C example correction is already covered. Mouse motion cache remains host-owned; terminal tracking-change callbacks and owner reset paths exist rather than persistent opaque C encoder settings. The C setter reset/NULL changes do not introduce new input encoding logic.
- **Glyph default:** At `0b7f9c156`, C Wrapper.new explicitly disables Glyph Protocol and NULL reset now restores false. Earlier `796f09a6f` restored true; this intermediate difference was inspected. The Ghostty core app keeps Glyph enabled. Rust `Glyphs::default` is enabled, has `set_enabled`, clears registrations on disable, and tests enable/disable behavior. Native oracle uses the core path. Preserve Rust/core app policy; changing it would port the C embedder policy to the wrong surface.
- **Versions, layouts and exports:** The version function/header, stable symbols for feature-disabled C builds, hidden Windows CRT markers, ELF version script, C enum MAX_VALUE/layout conventions, typed manifest and ABI golden gate all target the produced libghostty-vt binary. Rust has a separate Cargo version and typed linking/serialization contracts. Existing GHOSTSNP and Rust host protocols retain their version/compatibility checks; these C ABI changes neither alter GHOSTSNP wire data nor justify a protocol bump. Packed internal Style improvements remain performance-audit ownership.

## Validation and limitations

This was a read-only audit, with no repository edits or test/build executions by this agent. Evidence above is from implementations, callers and existing tests, not an independent test pass. No C ABI emulation or new benchmark is warranted: these changes normalize external layout/ownership, and their only per-cell conversion performance belongs to the absent C bridge. Root owns fresh native comparisons and semantic-port validation.

The exact map is `behavior-abi-commit-map.json` (array schema matching app map plus evidence/disposition/report) and `behavior-abi-prefix-map.json` (prefix keyed). It accounts for 85 combined behavior/ABI/documentation-overlap commits. In the final integration report, replace unfinished behavior statuses with validated port IDs; prefer app/performance evidence for overlapping rows rather than treating overlap as extra work.
