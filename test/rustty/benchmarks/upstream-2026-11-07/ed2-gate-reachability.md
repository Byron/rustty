# ED2 semantic prompt gate: independent read-only audit

Reviewed incoming `ce920296c` and merge `9bfa8ee9a`, plus connected Rust ingress, mutation, restore and copy paths. The merge has no additional terminal changes relative to its feature parent. No repository writes, builds, tests, replays or timing runs were performed for this audit.

## Required invariant

The new negative gate is safe if `seen == false` guarantees that **no retained row can carry a non-Output semantic row header**, and all future ways to create/import such a row make `seen` true. Tracking current Input/Prompt cursor content as upstream does is a conservative early positive. The ED2 heuristic examines row headers, not cell semantic values or tmux shell-marker maps. A false negative loses the existing scroll-before-clear behavior and discards output that should enter scrollback.

Use a sticky positive for the lifetime of that screen. Ordinary erases, OSC 133 C/D, dropping history, DECSTR, row recycling, and ending input must not clear it. A real fresh Screen/RIS may start false. The existing tmux and alternate-screen exclusions, protected-cell behavior, ED3, and explicit ED22 remain independent of the new gate.

## State paths

| Path | Evidence / requirement |
| --- | --- |
| OSC 133 A/N/P and continuation options | `terminal.rs::semantic_prompt` sets cursor Prompt and immediately sets row Prompt/Input. Set seen here. `osc133` dispatches all three actions through this helper. |
| OSC 133 B/I without A | `terminal.rs::osc133` sets cursor Input. B's following `index` creates Input row headers; I clears cursor semantics on explicit EOL. Set seen for both input actions, not only prompt actions. |
| Explicit linefeed/index and automatic wrap | `terminal.rs::index` marks a row Input when the cursor is semantic and EOL does not clear it. `print_wrap` restores cursor semantic state after index and separately marks Prompt continuations. These actual row-marking sites must also set seen, because public direct cursor mutation bypasses OSC. |
| Public cursor mutation | `Terminal::screen_mut()` returns `&mut Screen`; `Screen.cursor.semantic` is public. A caller may set Input, print across LF, then set Output directly before ED2. Updating only OSC, cursor-copy, or checking current cursor state at ED2 misses this valid path. Existing `tests/reflow_semantics.rs` and `tests/hyperlinks.rs` directly mutate cursor semantics. |
| Ordinary writes and public cell setters | `Screen::cursor_template` copies cursor semantics into cells. `Page::mark_cell` updates resource/dirty hints, never semantic row headers. Public `set_cell_text`/`set_cell_style` preserve row semantics; returned rows/cells are immutable views. `row_header_mut` and cell mutation are crate-private. An isolated semantic cell with an Output row does not make current ED2 scroll. |
| tmux OSC 133 | `tmux_shell.rs::tmux_osc133` directly assigns cursor Prompt/Input/Output and writes separate marker maps. Include semantic-entry hooks there, or rely on the actual row-marking hooks above for correctness. The ED2 native prompt heuristic is disabled by `tmux_graphics`, but `tmux_strings` can independently select this parser path; do not assume the exclusion always covers it. |
| Alternate cursor copies | `terminal.rs::switch_screen` copies the complete old cursor for mode47/1047 both ways and mode1049 entry, including Input/Prompt. Set the destination's sticky bit when a copied cursor is non-Output; do not replace a true destination bit with a false source bit. 1047 clears alternate content before copying its still-semantic cursor back. 1049 exit does not copy alternate semantics. |
| Saved cursor / DECRC | `save_cursor` retains a Cursor clone, but `restore_cursor` explicitly restores only selected attributes; semantic content is intentionally left unchanged. Saved semantic content alone is not a new ingress. Soft reset likewise preserves existing semantic cursor/content, so keep seen. |
| Screen and Terminal Clone | Both derive Clone and should preserve the sticky field automatically. `Screen::snapshot_viewport` has an explicit Screen literal and clones a row range; copy/derive seen there as well. This detached screen can be installed through the public mutable Screen reference. |
| Native binary checkpoint decode | `snapshot.rs::Decoder::screen` builds `Screen::new`, assigns decoded cursor, then installs decoded pages. Derive seen from current Input/Prompt cursor plus all resident semantic row headers before returning. Native additionally treats Prompt cells as a conservative positive (`src/terminal/snapshot/screen.zig:493`); matching this fallback is harmless. Do not require a newly serialized field. |
| Incremental history decode | `snapshot.rs::Decoder::next_inner`, accepted-page branch around1760, prepends decoded pages after limits/identity checks. Mark seen from the accepted page. A prompt can exist only in this later history, then become active through height growth/reflow or reverse scrolling. RIS deliberately preserves screen identity so history may still arrive afterward. Native already covers this in `snapshot/history.zig::decodePage`: compute prompt presence and set seen only after successful attachment. Rejected/omitted history need not set it. |
| JSON Screen decode | `screen/serde.rs::Deserialize` rebuilds all pages, restores current cursor and both history/active row semantics, then synchronizes cursor resources. Derive seen from these validated contents; an optional/skipped runtime field alone defaults false and is insufficient. Old JSON must remain compatible without protocol/schema changes. |
| Display-only page transfers | `screen/visual.rs::visual_copy` creates fresh Screen state but carries source pages and semantic headers; preserve/derive seen. `append_visual` adds another screen's pages, so OR source state or inspect imported headers. `prepend_visual` funnels through append. `visual.rs::VisualSnapshot::decode` rebuilds another fresh terminal around decoded pages; `restore_into` again puts restored pages into a new Screen and copies the live cursor. Both need propagation. Public visual restore can later feed ED2 on that primary screen. |
| Reflow, row rotation/copy, history unscroll | `screen/resize.rs::apply_reflow_row`, `screen.rs::install_row`, and page rotations preserve source row semantics within the same screen. With a sticky bit and correct imports, no fresh scan is required. Do not clear seen while blanking discarded source rows. Header metadata, rather than cell semantics, supplies the reflow semantic state. |
| Full reset | Normal `Terminal::reset` replaces the terminal with `with_limits`, so the fresh primary can start false. Subsequent incremental history attachment must update it. Alternate creation uses Screen::new plus the cursor-copy path above. tmux reset does not reconstruct all retained screen state; do not indiscriminately clear the bit there. |

## Minimal fresh regression set

Use 10 columns, 8 rows and enabled history. Let `out = "out\r\n" * 3`, `clear = "\x1b[H\x1b[2J"`, and OSC terminate with BEL or ST.

1. **B-only:** `out + OSC133B + "input\r\nmore" + clear`. No A is ever sent. The last populated row is an Input continuation, so history grows and active cells clear. The otherwise identical no-OSC control must remain a plain clear without new history.
2. **Copied Input:** `out + CSI?1047h + OSC133B + CSI?1047l + "input\r\nmore" + clear`. The only OSC133 was on the alternate screen; primary still scrolls on ED2. Mode47 can share this case. Mode1049 exit is a useful negative control because it retains primary semantics.
3. **Input-only checkpoint:** checkpoint/restore after `out + OSC133B + "input"`, before any continuation row exists; then `"\r\nmore" + clear`. Exercise fresh native/Rust decode and cross-decode. This catches deriving only row state while ignoring the active Input cursor.
4. **Existing prompt after cursor returned to Output:** `out + OSC133P + "prompt" + OSC133C + clear` (C is emitted at nonzero column, so it leaves the row mark). Also replay after DECSTR and after clone/checkpoint/JSON decode. It catches non-sticky state and decoding only the current cursor.
5. **Public cursor regression (Rust unit):** directly set `screen_mut().cursor.semantic = Input`, feed `"input\r\nmore"`, directly set Output, then clear. Compare history/active contents to the B-only stream. This is essential even if all native byte-stream cases pass.
6. **Imported row regression (Rust unit / existing snapshot fixtures):** restore a row-marked screen with Output cursor via JSON and via VisualSnapshot; ED2 must retain its prior scroll behavior. For incremental GHOSTSNP, put the only prompt in later history, finish decoding, grow height until it enters active rows, then ED2. Pair accepted vs omitted history when checking the derived flag.

Keep the existing recycled-row prompt regression meaningful: direct internal row-header setup must also set/derive seen, otherwise the new negative gate makes the test pass without testing recycled metadata. Existing `tests/semantic.rs` covers whole-row erasure and prompt scroll semantics, but lacks the B-only, public-cursor-before-Output, and import cases above.

## Conclusion

The optimization itself is safe and needs no serialized compatibility field. A mechanical gate plus OSC setter changes is insufficient on Rust's current API surface. The additions must cover actual row marking and every fresh-screen/import boundary above. Once those preserve the invariant, ordinary copy/reflow/delete operations need only retain the sticky value; a repeated scan on the ED2 fast path would undo the intended optimization.
